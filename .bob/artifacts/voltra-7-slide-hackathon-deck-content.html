SLIDE 02
How VOLTRA Works — 7-Stage Pipeline
The full technical flow from sensor ppm to operator advisory. One diagram, every stage.
Section headline
From dissolved gas to dispatch order —
in one automated pipeline.
7 Pipeline Stages (use a horizontal flow diagram on the slide)
01
Telemetry Ingestion
90-day CSV timeseries for all 18 transformers. Inputs: DGA gas ppm (H₂, CH₄, C₂H₆, C₂H₄, C₂H₂), top-oil temperature, load factor, dielectric rigidity, voltage level.
02
Feature Harmonisation
Column rename mapping (Hydrogen→H₂, Acethylene→C₂H₂), Duval ratio computation (C₂H₂/C₂H₄, CH₄/H₂), weather enrichment from Open-Meteo live API, physical telemetry normalisation.
03
Model 1 — Health Index Regressor
Random Forest Regressor (R²=0.72, MAE=5.88) on 470 Kaggle transformer units. Outputs: continuous Health Index score (13.4–90+), risk tier (LOW/MEDIUM/HIGH/CRITICAL), Remaining Useful Life in days.
04
Model 2 — DGA Fault Classifier
Random Forest Classifier (90.8% accuracy, F1=0.896) on 4,151 DGA rows. Outputs: one of 7 IEC 60599 fault classes (D1, D2, T1, T2, T3, PD, Normal) + per-class probability vector.
05
Grid Impact Ranker
5-factor composite score: HI (35%) + RUL (25%) + Fault Severity (20%) + MVA (10%) + Incident History (10%). Criticality multiplier applied (CRITICAL=2.0×, HIGH=1.5×). All 18 assets ranked highest-risk-first.
06
SHAP Attribution
SHAP TreeExplainer on both models surfaces top-3 causal gas features per asset. Operators see "Acetylene surge (+12.4 HI) indicates active arcing" — not a raw feature vector.
07
AI Advisory Layer
IBM Bob (Claude 3.5 Haiku) generates grounded plain-English maintenance directives from SHAP + fault class + RUL. Groq LPU (Llama-3.3-70B) produces instant grid inspection reports. Falls back to deterministic templates if API is unavailable — scoring never breaks.
Speaker note: Emphasise the isolation guarantee — "Stages 1–6 are pure Python + scikit-learn. Stage 7 wraps every LLM call in try/except. If IBM Bob is unreachable tonight, your grid scores still run. No dependency on external uptime for critical safety scoring."

Screen 1 — Live Grid Inspector (/grid)

Screen 2 — 7-Day Maintenance Plan

  • Crew pre-positioning recommendations driven by zone proximity (Zone-A/B/C/D clustering).
  • Downloadable per-asset action cards: DGA syringe sampling, bushing inspection, fan check, oil test procedures — the engineer takes this to the field.
Screen 3 — What-If Stress Simulator
  • Load slider: 0.80× (off-peak) → 1.00× (nominal) → 1.30× (peak A/C demand) → 1.50× (emergency overload).
  • Weather presets: Normal / Heatwave (>40°C) / Severe Thunderstorm.

  • Click a pin: popup shows name, coordinates, real-time health score, and live status.
  • Synced data grid alongside the map — clicking a grid row flies to the map pin, clicking a pin highlights the grid row. Pin count always equals grid row count (invariant enforced in code).
  • Live polling updates every 5 seconds via backend API — out-of-order updates dropped, stale reads rejected.
Screen 5 — Prediction Studio (/predict)
  • Upload a custom CSV of DGA sensor readings and get back a ranked risk table — the engineer can test readings from any transformer, not just the 18 in the fleet.
  • Manual entry mode: type in ppm values for H₂, CH₄, C₂H₄, C₂H₂, C₂H₆, temperature, load — get Health Index, fault class, and Bob advisory instantly.

SLIDE 06
Security, Explainability & Trust Architecture
Why grid engineers can trust this system. Covers SHAP, prompt injection defense, and the isolation guarantee.
Section headline
A score you can defend to a regulator.
An advisory you can act on immediately.
SHAP Explainability
  • Every score is decomposed into additive feature contributions. An HI of 67.3 is explained as: C₂H₂ +12.4, CH₄ +9.1, H₂ +5.6 — not a black-box number.
  • IBM Bob receives the top-3 SHAP features alongside the score. Its advisory says "Acetylene surge indicates active electrical arcing" — not a generic risk warning.
  • Operators can present SHAP attribution to regulators as documented scientific evidence for every maintenance decision.
Prompt-Injection Defense
  • Community hazard reports and field notes are filtered through regex guards before reaching any LLM — patterns like "ignore previous instructions", "system prompt override", "jailbreak" are caught and quarantined.
  • Rejected submissions are logged to rejected_submissions_log.csv for forensic security review.
  • A field report can only act as a bounded risk multiplier (max 1.25×). It can never lower a risk tier or override physical sensor data.
LLM Isolation Guarantee
  • All four AI integrations (IBM Bob, Groq, Gemini, Open-Meteo) are wrapped in try/except isolation. Core scoring and ranking runs on pure Python + scikit-learn — no API dependency.
  • The advisory_source field in every API response tells the engineer whether the advisory came from a real LLM or the deterministic fallback template.
  • Pydantic v2 validates every request body and sensor reading before it enters the pipeline — malformed data is rejected at the API boundary, not silently processed.

Transparent Limitations (show this — engineers respect honesty)
  • R² = 0.717 because public DGA datasets omit furan 2-FAL / DP measurements (IEEE C57.104 gap, not a modeling flaw).
  • T2 recall 74.3% — documented boundary overlap with T1/T3, flagged explicitly in every T2 advisory.
  • RUL uses calibrated piecewise — no run-to-destruction ground truth in public datasets.
